# CustomSosigModelFramework model addons (schema 1)

## Installation and selection

Framework: `BepInEx/plugins/NotGodlike-CustomSosigModelFramework/CustomSosigModelFramework.dll`.

Each addon is an independent data-only mod folder anywhere beneath `BepInEx/plugins`, containing `customsosig-model.json` and its declared assets. No addon DLL or framework source edit is required. Restart after installing/removing an addon. Discovered IDs are logged; malformed packages are rejected. Wrist Menu > `Custom Sosigs` lists `Sosig`, `Random`, and one choice per successfully loaded addon. Addon choices use optional `menuName` (or `displayName`); thus removing Metrocop removes its menu choice. `Sosig` restores native visuals and collision, while `Random` selects independently from all loaded addons for each Sosig. Changing a choice updates already spawned Sosigs and persists `[Models] ActiveModel` in `BepInEx/config/NotGodlike.h3vr.customsosigmodelframework.cfg`. If a saved addon is missing on restart, the framework falls back to `Sosig`.

## Author workflow

For a concrete local Unity authoring example, see [`Templates/UnityModelAddon/README.md`](../Templates/UnityModelAddon/README.md). It contains the prepared MW4 Milsim FBX/GLB, textures, and all Mixamo/weapon source clips; it is not an installable or freely redistributable mod.

1. Start from [`Templates/ModelAddon/README.md`](../Templates/ModelAddon/README.md) and its complete sample manifest and Mixamo/LPSP source mapping. Copy that folder to `Addons/YourModel` only after preparing your own model. Give it a unique `id`, `displayName`, appropriate `heightMeters`, and relative asset paths. Disable/remove `eyes` unless this model has matching lens UV regions. All files must stay inside the addon directory.
2. Provide a skinned GLB 2.0 with exactly one skin and one mesh (multiple material primitives allowed). This version supports humanoids, not arbitrary creatures. Vertex count per primitive must fit Unity's legacy 16-bit indices (<=65000); skeleton has <=255 bones.
3. Map other rig names with `boneAliases`, e.g. `{ "source": "mixamorigHips", "role": "Pelvis" }`. Roles refer to the engine's canonical humanoid vocabulary; no Valve model is required. Mandatory roles: Pelvis, Spine, Spine1, Spine2, Neck1, Head1; L/R_Clavicle, UpperArm, Forearm, Hand, Thigh, Calf, Foot. Optional toe roles L/R_Toe0 improve sole markers; finger roles follow L/R_Finger0..4 and suffixes 1/2. Alias names must match the actual target GLB bones.
4. Prepare an animation source JSON array, each entry `{ "role": "walk", "source": "H:/path/walk.fbx", "bind": "H:/path/reference.fbx" }`. `bind` is optional; use a proper reference skeleton for static weapon pose FBXs. The complete required role list is the `animations` array in the template. A file may serve multiple compatible roles, but every role must resolve; missing animations do not silently become T-poses.
5. Run `Tools/prepare-model-addon.ps1 -Manifest Addons/YourModel/customsosig-model.json -ModelGlb H:/path/model.glb -AnimationSources H:/path/animation-sources.json`. It converts the mesh and retargets clips to this rig, applying bone aliases. Target skeleton/bone indices must match the target model; do not copy Metrocop's converted clips onto another rig.
6. Supply PNG textures declared in `materials`, ordered by GLB material index. `textureConvention: "gltf-images"` flips V for images taken directly from the GLB; `"external-flipped"` keeps V for source PNGs that are vertically inverted relative to embedded images (Metrocop). Test visually; do not flip both images and UV.
   Optional `surface: { "smoothness": 0.4, "metallic": 0.0 }` overrides the shared Visual settings for that addon only. Unity Standard shader uses smoothness, approximately the inverse of roughness: lowering smoothness makes a surface less glossy. Both values must be between 0 and 1. Existing addons without `surface` retain their previous shared settings.
   Optional `impactEffect: "meat"` enables the framework's red blood VFX on this addon's custom body hitboxes. Optional `bloodMask` and `bloodNoise` point to PNG assets inside the addon; the framework bakes the mask's red channel and the noise into a short-lived splash texture for Unity 5.6's legacy particle shader. The supplied ShaderLab source is a visual reference, not loaded directly at runtime. Omit the option (or use `"native"`) to retain native Sosig impacts. Stock ballistic particles/decals and mustard burst visuals are suppressed without changing penetration or blood-loss logic. All custom models also suppress the native Sosig explosion and gib visuals on death; native armor keeps its own impacts.
7. Build/install with `Tools/build-plugin.ps1` and `Tools/install-plugin.ps1` while H3VR is closed. Each direct subfolder of `Addons` is packaged independently. Select the new addon in Wrist Menu, or set `ActiveModel` to its ID in config before starting the game.

## Optional eyes

`eyes` contains `enabled`, `materialIndex`, `radiusU`, `radiusV`, `darkThreshold` and `centers: [{u,v}, ...]`. Coordinates are normalized repeat-tile UVs with Unity's bottom-left convention. Regions must fit inside 0..1. Only dark lens triangles inside them get the unlit blue material; the original face material remains on other triangles. Global BlueEyeEmission/EyeEmissionIntensity can override visibility/intensity.

## Scope and validation

The framework owns native Sosig attachment, presentation state, weapon driving, humanoid hitboxes, grounding and ragdoll. Addons own mesh, material textures, retargeted clips, semantic bone mapping, model height and optional eye regions. The existing native AI/health/armor behavior is unchanged. Legacy Visual.HeightMeters is migrated but addon height is authoritative.

Armor interception uses separate, model-specific colliders. At addon load, the framework measures skinned bind-pose vertices assigned to each torso, head, and leg segment, adds a small clearance, and enables those colliders only while the corresponding native Sosig link has active wearable armor. The optional `armorHitboxScale` manifest field (default `1`, allowed `0.25`-`1.5`) scales the dimensions of these interceptors around each segment center; use it to trim oversized envelopes caused by protruding gear. The MW4 Milsim addon uses `0.38` (about 2.6 times smaller per dimension). The blue `Armor Hitbox` overlay uses the same collider dimensions; the original body colliders remain unchanged for ragdoll physics. Correct skin weights and bone aliases are important for armor placement. Check the resulting silhouette and protection in-game after changing this scale.

Converters are offline Node/three tools; raw FBX/GLB is not loaded by the game. JsonUtility manifest loading and gameplay behavior require an H3VR run; static packaging checks do not establish VR correctness. Existing render materials are opaque Standard/Diffuse, with Unlit/Color lens surfaces; complex transparent materials are not supported in schema 1. The addon is a local mod package, not automatically a published Thunderstore release.

Before publishing, obtain rights to distribute model, textures and animation assets. The user's Low Poly Shooter Pack is not licensed for unrestricted standalone asset redistribution merely because it is included in this local addon.
